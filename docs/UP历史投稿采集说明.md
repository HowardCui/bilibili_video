# UP 历史投稿采集说明

Web 页面中的“采集或更新历史投稿”同时承担首次补全和后续刷新两种用途。

## 首次采集

采集按发布时间从新到旧分页进行，每页最多 30 条。一次后台执行最多处理 20 页，也就是最多 600 条。

如果 UP 的投稿超过 600 条，第一次执行结束后，任务会进入 `PAUSED`，分页游标也会保存。页面会提示“本批采集已完成，仍有历史投稿，可继续采集”。再次点击按钮时，采集会从上次游标继续，不会从第一页重复开始。页面上的投稿数可能从 600 继续增加，这是正在补全更早的投稿。

数据库使用 `(uploader_id, bvid)` 作为视频唯一键。投稿数增加代表发现了新的 BV 号，不是重复插入同一条视频。

## 更新已有数据

完整历史采集结束后，任务状态会变为 `SUCCEEDED`。此时再次点击按钮会创建新任务，并从第一页重新采集。

重新采集时：

- 已存在的 BV 号会更新播放、点赞、投币、收藏、评论、弹幕和分享数据。
- 新发布的视频会写入数据库。
- 找不到的单项字段仍按 `0` 保存。
- 同一个 BV 号不会重复增加投稿数。
- 每次成功保存还会写入指标快照，供趋势图使用。

如果旧记录只有播放量、其他指标为 `0`，需要等首次历史采集完整结束，再执行一次从第一页开始的新采集，才能刷新前面已经保存的视频。

## 状态判断

- `RUNNING`：当前批次正在执行。不要在页面提示“数据获取中”时重复点击。
- `PAUSED`：本批最多 20 页已经处理完，但接口仍有下一页；可以点击按钮从已保存的游标继续。
- `SUCCEEDED`：已经到达接口返回的最后一页。下一次点击将从第一页刷新已有数据。
- `FAILED`：本次请求失败，可根据页面提示稍后重试。已经保存的数据不会被删除。

UP 投稿较多时，补齐详情指标需要逐条请求视频详情，耗时会明显增加。刷新页面或重启 Web 服务不会清空已保存的分页游标和视频数据。
