# Ranking Collector 数据模型设计

## 范围

本阶段只完成 `ranking_collector/models.py` 及其单元测试，不实现数据库、
采集服务或定时调度。模型负责隔离 Bilibili 原始 JSON，并为后续持久化和
趋势计算提供稳定、类型明确的数据契约。

## 模型

- `VideoInfo`：BV 号、标题、UP 主、分区和发布时间。
- `VideoMetrics`：播放、点赞、投币、收藏、评论、弹幕和分享计数。
- `RankingItem`：视频信息、指标和榜单排名。
- `RankingSnapshot`：分区、采集时间和不可变榜单条目集合。
- `MetricChange`：两次采集之间的指标增量、排名变化、间隔和每小时播放增量。
- `CollectionResult`：单个分区的采集结果，包含 `succeeded`、
  `error_message` 和可选的 `snapshot`。

所有模型使用不可变 `dataclass`。日期时间必须带时区，排名必须为正整数，
指标必须为非负整数。

## 原始数据转换

`RankingItem.from_bilibili` 接收单条 Bilibili 原始数据以及由调用方提供的
分区、排名和采集时间。

- `bvid`、标题、UP 主、分区和发布时间等关键数据严格校验。
- 计数类字段缺失或为 `None` 时按 0 处理。
- 布尔值、错误类型和负数不作为有效计数。
- 不在模型层吞掉关键数据错误，调用方可以据此标记采集失败。

## 采集结果约束

成功结果必须携带快照且没有错误信息；失败结果必须携带非空错误信息且不携带
快照。一次任务包含多个分区时，每个分区产生一个 `CollectionResult`，整体的
全部成功、部分成功或全部失败由后续 service 汇总。

## 测试

测试覆盖正常 JSON 转换、缺失计数默认值、关键字段缺失、错误计数类型、负数、
非法排名、无时区日期时间，以及成功/失败采集结果的不变量。测试先失败，再以
最小实现使其通过。
