# 后台日志说明

项目使用后台日志记录 Web 服务、排行榜采集和自动化包装入口的运行情况。日志用于日常检查和故障定位，不在 Web 页面展示，也不替代 SQLite 中保存的业务数据。

## 日志位置

| 文件 | 记录内容 |
|---|---|
| `logs/web.log` | Web 服务启动、停止、总结任务及未处理异常 |
| `logs/ranking.log` | 排行榜分区采集、Cookie 后备和采集结果 |
| `logs/automation.log` | 单次采集包装入口的开始、结束和最终状态 |

日志目录已加入 `.gitignore`，不应提交到 Git。每行都是一条 UTF-8 JSON 记录，时间统一使用北京时间并带 `+08:00`。单个日志文件最大 5 MB，每类最多保留 5 份轮转文件。

## 常用字段

| 字段 | 含义 |
|---|---|
| `timestamp` | 日志产生时间，北京时间 |
| `level` | `INFO`、`WARNING` 或 `ERROR` |
| `module` | 产生该日志的模块 |
| `event` | 稳定的事件名称，适合筛选 |
| `message` | 面向日常检查的中文说明 |
| `task_type` | 任务类型，例如 `ranking` 或 `automation` |
| `task_id` | 视频总结、UP 采集等任务的任务 ID |
| `run_id` | 排行榜采集批次 ID |
| `partition` | 排行榜分区名称 |
| `duration_ms` | 本次操作耗时，单位为毫秒 |

没有对应信息的字段会写为 `null`，不代表任务失败。

## 排行榜采集状态

在 `logs/automation.log` 中，以最新一条 `automation_finished` 判断单次包装入口的结果：

| 状态 | 含义 |
|---|---|
| `SUCCEEDED` | 全部分区完成并通过数据库核验 |
| `PARTIAL_FAILED` | 部分分区成功，部分分区失败 |
| `FAILED` | 本轮没有得到可用的完整结果 |
| `SKIPPED_ALREADY_RUNNING` | 检测到另一轮采集或测试中的并发占用，本次主动跳过 |
| `TIMED_OUT` | 采集超过包装入口的超时时间 |

`SKIPPED_ALREADY_RUNNING` 是并发保护的正常结果，不会覆盖已有数据。运行测试时也可能产生带模拟 `run_id` 的跳过记录，因此不要只搜索某一条 `WARNING`；应结合时间，查看最新一次完整的开始和结束记录。

`logs/ranking.log` 中的 `ranking_collection_started` 和 `ranking_collection_finished` 表示一轮真实采集的边界。两者的 `run_id` 应一致，中间会记录各分区的保存结果。

## Cookie 后备警告

以下警告不等于采集失败：

```text
ranking_cookie_fallback
排行榜匿名请求失败，改用 Cookie 后备
```

它表示匿名请求触发了站点风控，程序按照“匿名优先、失败后再使用 Cookie”的策略重试。若后面出现相同采集批次的分区成功和 `SUCCEEDED`，本轮采集就是成功的。只有后续出现分区失败、`PARTIAL_FAILED` 或 `FAILED` 时才需要继续排查。

日志会对 Cookie、API Key、Authorization、WBI 签名和敏感本地路径进行脱敏。检查问题时也不要手动把这些内容复制进日志。

## 日常检查命令

查看最新日志：

```powershell
Get-Content .\logs\automation.log -Tail 30
Get-Content .\logs\ranking.log -Tail 50
Get-Content .\logs\web.log -Tail 50
```

持续观察正在运行的采集：

```powershell
Get-Content .\logs\automation.log -Tail 20 -Wait
Get-Content .\logs\ranking.log -Tail 30 -Wait
```

筛选警告、错误和最终状态：

```powershell
Select-String -Path .\logs\*.log* -Pattern '"level": "WARNING"|"level": "ERROR"'
Select-String -Path .\logs\automation.log* -Pattern 'automation_finished'
Select-String -Path .\logs\ranking.log* -Pattern 'ranking_collection_finished'
```

按采集批次查询，例如 `run_id` 为 `14`：

```powershell
Select-String -Path .\logs\*.log* -Pattern '"run_id": 14'
```

## 判断一次采集是否正常

建议依次确认：

1. `automation.log` 中存在 `automation_started`。
2. `ranking.log` 中存在对应的 `ranking_collection_started`。
3. 全站、知识、科技、游戏、生活分别出现分区结果。
4. `ranking.log` 中出现相同 `run_id` 的 `ranking_collection_finished`。
5. `automation.log` 最终出现 `SUCCEEDED`。

Windows 任务计划程序中的 `LastTaskResult` 为 `0`，并且日志最终为 `SUCCEEDED`，即可确认计划任务和业务采集都执行成功。`NumberOfMissedRuns` 为 `0` 表示没有错过计划时间。

启用 Windows 任务计划程序后，应保持 Codex 定时自动化和项目内 `--schedule` 关闭，避免多个调度器在同一时间触发采集。
