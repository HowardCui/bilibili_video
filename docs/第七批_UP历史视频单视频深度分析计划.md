# 第七批：UP 历史视频单视频深度分析

> 基于现有“UP 历史视频分析”和“UP 分析数据可视化”能力，进一步下钻到单个视频维度，分析观众在视频中的互动时间分布以及评论区的地域与文本特征。

## 一、功能目标

在 Web 端的“UP 分析”页面中，用户可以从某个 UP 的历史投稿列表中选择一个视频，并在同一页面的“视频互动分析”区域查看该视频的：

- 弹幕密度趋势；
- 弹幕高峰时间段；
- 评论 IP 地域统计；
- 评论高频词与词云。

核心希望回答三个问题：

1. **观众在视频的什么时间段最活跃？**
2. **评论用户主要来自哪些地区？**
3. **评论区主要在讨论什么？**

本批次优先完成稳定、可复用的基础分析能力，不扩展到复杂情感分析、主题聚类或 LLM 总结。

---

复用现有“UP 分析”页面中的历史投稿列表。

用户从历史投稿列表中选择一个视频后，下方“视频互动分析”区域自动切换为当前视频对应的数据。

示意：

│ UP 基本信息                   │
└──────────────────────────────┘

### 2.2 状态管理

历史投稿列表、视频基本信息、弹幕分析和评论分析共享同一个当前选中视频对象。

切换视频后：

- 视频基本信息同步更新；
- 弹幕分析结果自动刷新；
- 评论分析结果自动刷新；
- 单个模块加载失败时，不影响其他模块和 UP 历史投稿列表。

## 三、弹幕密度分析

### 3.1 功能定义

弹幕密度用于分析：

> 视频的哪一段时间弹幕最多，哪一段时间弹幕较少。

不是单纯统计视频总弹幕数，而是按照视频播放时间对弹幕进行分桶聚合。

例如：

```text
时间        弹幕数量
0-30s        83
30-60s      121
1:00-1:30   176
1:30-2:00   420
2:00-2:30   510
2:30-3:00   238
...
```

### 3.2 数据要求

建议保留每条弹幕的原始时间戳，而不是只保存聚合结果。

基础字段至少包括：

```text
video_id
danmaku_time
danmaku_text
created_at
```

分析时再按照不同粒度动态聚合。

### 3.3 时间粒度

第一版支持：

- 短视频：10 秒或 30 秒；
- 长视频：60 秒。

后续可以继续增加：

- 5 秒；
- 5 分钟；
- 自定义时间窗口。

### 3.4 可视化

使用时间序列折线图或面积图展示弹幕密度趋势。

```text
弹幕数
500 |                ╭─╮
400 |             ╭──╯ ╰╮
300 |        ╭────╯      ╰╮
200 |    ╭───╯             ╰──╮
100 |────╯                     ╰────
    └──────────────────────────────
     0    2    4    6    8   10   12
                  视频时间 / min
```

鼠标悬停时展示：

```text
03:00 - 03:30
弹幕：487 条
占全部弹幕：3.8%
```

## 四、弹幕高峰区间

除了完整时间轴趋势外，自动提取弹幕最密集的 Top 时间段。

示例：

| 时间段 | 弹幕数 | 占比 |
|---|---:|---:|
| 03:20–03:50 | 623 | 4.8% |
| 07:10–07:40 | 518 | 4.0% |
| 10:30–11:00 | 491 | 3.8% |

第一版只需要识别高峰区间，不进一步解释高峰形成原因。

后续可以扩展为：

- 高峰时间段弹幕关键词；
- 高峰时间段情绪分析；
- 高峰时间段内容摘要；
- 视频高潮识别。

## 五、评论采集与缓存

### 5.1 评论数据

新增或完善视频评论数据存储。

建议核心字段：

```text
comment_id
video_id / bvid
uid
content
like_count
reply_count
ip_region
comment_time
fetched_at
```

### 5.2 评论采集状态

建议增加评论采集任务状态表，例如：

```text
video_comment_collection
```

记录：

```text
video_id
status
comment_count
started_at
completed_at
error_message
```

### 5.3 缓存逻辑

用户选择视频后：

```text
已有评论缓存
    ↓
直接读取 SQLite

没有评论缓存
    ↓
触发采集
    ↓
写入 SQLite
    ↓
生成分析结果
```

避免用户每次切换视频时重复请求远端数据。

## 六、评论 IP 地域分析

### 6.1 目标

统计评论用户 IP 属地的分布情况。

例如：

```text
广东     18.7%
浙江     13.2%
江苏     11.5%
上海      8.3%
北京      7.9%
其他     40.4%
```

### 6.2 第一版展示形式

优先使用：

- 横向条形图；
- Top 地区排行榜；
- 地区占比。

示意：

```text
评论 IP 地域

广东 ███████████████ 18.7%
浙江 ███████████     13.2%
江苏 █████████       11.5%
上海 ██████           8.3%
北京 █████            7.9%
```

第一版不强制实现中国地图，以降低前端复杂度和移动端适配成本。

### 6.3 异常处理

需要支持：

- IP 属地缺失；
- 部分评论无地域；
- 评论数量过少；
- 评论接口返回不完整。

页面应显示明确的样本说明，不因部分地域缺失导致整个模块失败。

## 七、评论文本分析

### 7.1 文本清洗

评论文本复用现有弹幕词云的文本处理流程：

```text
原始文本
 ↓
清洗
 ↓
停用词
 ↓
分词
 ↓
词频
 ↓
词云
```

建议将通用能力抽象为统一文本分析模块：

```text
text_analysis
```

输入：

```text
List[str]
```

输出：

```text
word_frequency
top_keywords
wordcloud
```

之后弹幕和评论均可复用：

```text
弹幕 ──→ text_analysis
评论 ──→ text_analysis
```

### 7.2 评论分析展示

至少包含：

- 评论词云；
- 高频关键词 Top N；
- 关键词出现次数。

示例：

```text
高频关键词

剧情      582
制作      491
笑死      438
更新      361
UP主      298
```

## 十一、异常与降级处理

需要验证以下异常情况：

- 视频没有弹幕；
- 弹幕数据为空；
- 弹幕缓存不完整；
- 评论关闭；
- 评论数量过少；
- 评论接口请求失败；
- 评论 IP 属地缺失；
- 部分评论字段缺失；
- 词云无法生成；
- 单个视频分析数据异常；
- 历史数据格式兼容问题。

要求：

> 单个视频的弹幕或评论分析失败，不得影响 UP 历史投稿列表、UP 整体分析和其他视频的正常使用。

---

## 十二、第一版暂不实施

为控制本批次范围，以下功能暂不纳入第一版：

- 评论情感分析；
- 弹幕情感分析；
- LLM 评论总结；
- LLM 弹幕总结；
- 评论主题聚类；
- 用户画像；
- 地域与评论内容交叉分析；
- 弹幕情感随时间变化；
- 自动识别视频高潮内容；
- 评论关系网络；
- 中国地图；
- 高峰时间段自动解释。

这些功能可以在单视频基础分析稳定后继续增加新的业务批次。

---

## 十三、验收标准

### Web 联动

- 可以从 UP 历史投稿列表选择视频；
- 切换视频后分析区域正确刷新；
- 当前视频信息准确；
- 移动端布局正常。

### 弹幕分析

- 能正确按照时间窗口统计弹幕；
- 弹幕密度趋势正确；
- 可以识别 Top 弹幕高峰区间；
- 可展示时间段、弹幕数和占比；
- 无弹幕视频可以正常降级。

### 评论分析

- 评论可以正确采集并缓存；
- 重复访问不会无意义重复采集；
- IP 地域统计正确；
- 地域百分比计算正确；
- 评论词频和词云可以生成；
- 评论样本不足时提供说明。

### 系统稳定性

- 单模块异常不影响整个 UP 分析页面；
- 数据库写入失败有日志记录；
- 外部接口异常可以降级；
- 不新增重量级前端依赖；
- 不破坏已有排行榜、UP、总结和长期趋势功能。

## 第八批：数据保留、隔离清理与数据库备份

> 原“最后一批”自动顺延为第八批；后续新增业务功能批次时继续自动顺延，并始终保持最后实施。

- 完成只读存储统计、增长估算和清理候选报告。
- 完成 30 天缓存隔离、14 天恢复窗口和人工永久删除入口。
- 完成 SQLite 分层备份、完整性检查和恢复验证。
- 验证排行榜、UP、总结、长期趋势以及单视频互动分析所需数据不会进入清理范围。
