# Shiny 本地综合网站实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `127.0.0.1:8000` 提供 Shiny Core 本地综合网站，包含只读排行榜和可持久化、可恢复、可重试的视频总结流程。

**Architecture:** `web_app/` 使用 Shiny Core 按排行榜和视频总结拆分 UI、Server、查询、Repository 和 Service。应用级后台执行器复用现有视频处理与总结流水线，SQLite 是任务状态事实来源；自定义 CSS 实现参考图的深色橙金仪表盘视觉。

**Tech Stack:** Python 3.12/3.13、Shiny for Python、SQLite、pytest、现有 `ranking_collector`、`video_processing` 和 `summarization` 模块。

## Global Constraints

- 正式启动必须绑定 `127.0.0.1:8000`，不得默认绑定 `0.0.0.0`。
- 不使用 React、Vite、Tailwind CSS、TypeScript 或 FastAPI。
- 保留并复用现有排行榜采集、调度、比较、视频处理和总结逻辑。
- 类不使用装饰器，包括不使用 `@dataclass`。
- Shiny 官方函数装饰器允许使用。
- 所有测试使用普通 pytest 函数，不写测试类。
- 不使用 Playwright 或其他浏览器自动化；浏览器 UI 由用户按清单手动验收。
- 排行榜网页只读，不提供采集或调度控制。
- Cookie、API Key、堆栈、模型原始错误和本地绝对路径不得显示在页面。
- 同一 BV 号最多一个活跃总结任务；成功结果默认复用。
- 启动时自动重新排队 `PENDING` 和遗留 `PROCESSING` 任务；失败任务支持手动重试。
- 动画必须支持 `prefers-reduced-motion`。
- 保持原有 `--once` 和 `--schedule` 行为不变。
