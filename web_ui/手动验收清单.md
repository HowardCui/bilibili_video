# Web UI 手动验收清单

本文用于人工验收本地 Shiny 应用。自动化测试不能替代这里的交互、响应式布局和视觉检查。

## 验收准备

- [ ] 使用 Python 3.12 或 3.13 执行 `python -m pip install -e ".[dev]"`，安装成功且没有 README 编码错误。
- [ ] 执行 `python -m web_app.app`，控制台显示监听 `127.0.0.1:8000`。
- [ ] 只从本机访问 `http://localhost:8000`；确认页面不能通过 `0.0.0.0`、局域网地址或公网地址访问。
- [ ] 使用不含真实密钥的受控测试配置、测试数据库或替身 runner 准备各状态。验收本清单时不要触发真实 Bilibili 采集或真实模型调用。
- [ ] 准备五个分区各 100 条的当前快照、上一份快照，以及无基线、陈旧、当前为空和最近采集失败但存在上一份有效数据的受控样本。
- [ ] 准备等待、处理中、成功、失败、重复提交、重试和重启恢复所需的受控总结任务。

## 导航与整体框架

- [ ] 首次打开页面可见“排行榜”和“视频总结”两个导航入口，默认入口与设计一致。
- [ ] 两个入口可来回切换；切换后标题、内容和选中态准确，没有内容叠加、闪烁或页面级错误。
- [ ] 对照 `web_ui/网站完整设计.md` 及参考图检查外框、品牌侧栏、导航位置、内容留白、网格间距和圆角。
- [ ] 检查标题、说明、状态、数据和操作的视觉层级；主要信息不会被装饰元素抢占注意力。
- [ ] 检查背景、面板、边框、正文、弱化文字、强调色、成功色和失败色的颜色关系及对比度。
- [ ] 检查信息密度：桌面端能快速扫描主要指标和 Top 100，平板/手机端没有过度拥挤或大片无效空白。
- [ ] 页面及表单中看不到 API Key、Cookie 内容或 Cookie 文件内容，也没有编辑秘密的入口。

## 排行榜

- [ ] 分区选择器恰好提供“全站、知识、科技、游戏、生活”五个分区，逐一切换后标题、状态和数据均对应当前分区。
- [ ] 每个有数据的分区最多展示 Top 100；序号连续，标题、UP 主、分数等列对齐，长文本不会破坏布局。
- [ ] 验证正常比较（`VALID`）：上升、下降、新上榜、跌出榜单及变化指标均与两份受控快照一致。
- [ ] 验证无基线（`NO_BASELINE`）：明确显示“暂无对比基线”，不会伪造变化值。
- [ ] 验证陈旧数据（`STALE`）：明确显示“数据已陈旧”，仍能辨认数据时间与来源。
- [ ] 验证当前榜单为空（`EMPTY_CURRENT`）：明确显示“当前榜单为空”，空态不显示误导性的 Top 100 或变化值。
- [ ] 验证当前数据（`CURRENT`）：状态、采集时间和 Top 100 来自最新完整快照。
- [ ] 验证上一份有效数据（`LAST_VALID`）：最近一次分区采集失败时显示“上一份有效数据”，且不会把失败批次的部分数据当作当前榜单。
- [ ] 验证完全无数据（`NO_DATA`）与查询失败态：提供清晰、非敏感的说明，不显示 traceback、本机路径或凭据。
- [ ] 横向滚动 Top 100 表格时，页面主体不被撑出视口；键盘和触控板均可完成浏览。

## 视频总结

- [ ] 提交合法 Bilibili 视频 URL 后创建任务，当前任务卡和历史记录出现同一任务。
- [ ] 提交空值、非 Bilibili 域名、非法 BV 号等无效输入时，页面给出可理解的校验提示且不创建任务。
- [ ] 同一视频存在 `PENDING` / `PROCESSING` 任务时重复提交，复用现有任务而不是创建重复任务。
- [ ] 同一视频已有成功任务且没有活动任务时再次提交，复用已有成功结果。
- [ ] 历史任务按最新创建时间优先显示，状态、尝试次数、视频标识和时间信息一致；选择历史任务能显示对应状态或结果。
- [ ] `PENDING` 显示等待状态和等待动画，不提前显示结果或“重试”操作。
- [ ] `PROCESSING` 显示当前规范阶段、处理动画并自动轮询；未知阶段使用安全的通用文案。
- [ ] `SUCCEEDED` 停止轮询并显示存在的结果分区：视频信息、一句话总结、详细总结、章节、关键观点、关键词和重要时间点；缺失的可选分区不会产生空白卡片。
- [ ] `FAILED` 停止轮询，只显示安全、可操作的失败说明，不显示底层异常、traceback、API Key 或本机路径，并提供“重试”。
- [ ] 对失败任务执行重试后，只创建一个关联的新尝试；原失败记录保留，尝试次数增加，新任务进入等待/处理流程。
- [ ] 连续点击提交或重试不会创建多个并行重复任务；按钮反馈和最终状态一致。

## 动效与无障碍偏好

- [ ] 默认设置下，等待、处理中、成功和失败四种状态的动效/视觉反馈可区分，且不会遮挡文字或操作。
- [ ] 在操作系统或浏览器启用“减少动态效果”（`prefers-reduced-motion: reduce`）后重新加载：动画和过渡被关闭或显著减少，四种状态仍可仅凭文字、图标或颜色之外的语义信息识别。
- [ ] 使用键盘完成导航切换、分区选择、URL 输入、提交、历史选择和重试；焦点顺序与可见焦点样式清楚。

## 响应式布局

- [ ] 桌面（建议 1440×900）：侧栏、导航、指标、变化区域和 Top 100 层级接近参考图，主要内容无需横向滚动。
- [ ] 平板（建议 768×1024，并检查横竖屏）：布局按断点重排，卡片无重叠，触控目标和间距足够。
- [ ] 手机（建议 390×844，并补查 320 px 宽）：导航和面板单列可读，文本不截断，页面本身无横向滚动；只有表格容器可横向滚动。
- [ ] 在三类尺寸分别检查排行榜和视频总结两个入口，并与参考图比较外框、侧栏、间距、层级、颜色和信息密度。

## 关闭与重启恢复

- [ ] 在受控 runner 阻塞时分别留下一个 `PENDING` 和一个 `PROCESSING` 任务，然后正常停止应用。
- [ ] 重新执行 `python -m web_app.app` 后，两项未完成任务都被恢复并各自只调度一次；原 `PROCESSING` 先回到可恢复的待处理状态。
- [ ] 已成功和已失败任务在重启后仍存在，结果、错误的安全文案、尝试次数和重试关联未丢失。
- [ ] 重复启动/初始化不会重复调度同一任务；关闭后不再接收新提交，已排队任务留待下次恢复。
