# 本地综合网站完整设计

## 1. 目标与范围

建设一个仅限本机访问的综合网站。用户启动 Python 服务后，通过
`http://localhost:8000` 使用排行榜和视频总结功能。

第一阶段同时交付：

- 排行榜页面，读取现有 SQLite 榜单数据并展示实时比较结果。
- 视频总结页面，对接现有 Bilibili 视频处理与 AI 总结流水线。
- 持久化的视频总结任务、进度、结果、自动恢复和手动重试。
- 参考 Portfolio Dashboard 图片的深色、橙金色仪表盘视觉。

网站不包含公网部署、用户系统、网页内采集控制、密钥编辑、ASR、向量问答和多用户任务调度。

## 2. 工程边界

网页前端独立放在 `web_ui/`：

```text
web_ui/
├── 网站完整设计.md
├── package.json
├── vite.config.ts
├── tsconfig.json
├── src/
├── public/
└── tests/
```

后端放在 `web_app/`，负责 FastAPI 应用、JSON 接口、静态资源托管、排行榜查询和总结任务调度。现有 `ranking_collector/`、`video_processing/` 和 `summarization/` 继续保持各自业务职责。

正式本地运行时，FastAPI 同时提供 API 和 `web_ui` 的编译产物。开发时使用 Vite 热更新，并将 `/api` 请求代理到 FastAPI。

## 3. 技术架构

```text
浏览器
  → React + TypeScript 单页应用
  → FastAPI /api
      ├─ 排行榜查询服务
      │   └─ 现有 ranking.db 和快照比较逻辑
      └─ 视频总结任务服务
          ├─ SQLite 持久化任务、执行状态和结果
          ├─ 单机后台执行器
          └─ 现有视频处理与总结流水线
```

采用 React、Vite、Tailwind CSS 和 TypeScript。FastAPI 只绑定 `127.0.0.1:8000`，不监听局域网地址。React 不直接理解数据库行或 Python 内部对象，只消费稳定的 Web Schema。

排行榜页面只读。采集继续由现有 CLI 和调度器执行，网页不提供立即采集、启动调度器或停止调度器的操作。

## 4. 视觉系统

参考图只定义视觉语言，实际内容替换为排行榜和视频总结。

### 4.1 风格

- 页面背景使用暖橙色外框，应用主体使用炭黑色大圆角容器。
- 侧边栏、内容区和信息卡通过不同层级的深灰色区分。
- 橙色为主要操作与主趋势强调色，金黄色为次级指标色。
- 绿色表示成功或正向增长，红橙色表示失败或负向变化。
- 文字分为高亮标题、正文、辅助说明和弱化元数据四个层级。

### 4.2 设计 Token

统一定义并复用：

- 页面、侧栏、内容面板和悬浮卡片的背景色。
- 主色、次强调色、成功色、失败色和警告色。
- 4 像素基础间距体系。
- 小、中、大三档圆角。
- 面板边框、柔和阴影和焦点环。
- 快速反馈、阶段切换和页面过渡三档动画时长。

所有公共组件只通过 token 使用颜色、间距、圆角和阴影，避免散落的任意值。

## 5. 应用框架与导航

桌面端采用参考图中的窄侧栏布局：

- 顶部显示网站标志。
- 主导航包含“排行榜”和“视频总结”。
- 当前入口以橙色竖线、图标高亮和可访问状态共同标识。
- 底部保留服务状态或帮助入口。

平板端收窄侧栏，只显示图标和提示文字。手机端改为底部双入口导航，内容区域占满可用宽度。

公共页面框架包含：侧边导航、页面标题区、内容容器、全局错误提示和后端连接状态。

## 6. 排行榜页面

### 6.1 页面结构

- 顶部展示页面标题、当前快照时间、数据新鲜度和分区切换。
- 主图表展示排名趋势、播放增长或快照变化；视觉上沿用参考图的折线、点线和柱形组合。
- 右侧摘要显示换血率、快速上升、新进榜和其他核心指标。
- 下方状态卡展示持续在榜、新进榜、跌出榜、排名变化和每小时播放增长。
- Top 100 使用可横向滚动的数据表，至少展示排名、标题、UP 主、播放、点赞、投币、收藏、评论、弹幕和分享。

分区至少包含全站、知识、科技、游戏和生活。

### 6.2 状态展示

- `CURRENT`：当前有效比较。
- `LAST_VALID`：展示上一份有效比较，并明确来源时间。
- `NO_BASELINE`：没有可供比较的上一份快照。
- `STALE`：快照间隔超过 24 小时，继续展示变化但不显示有效换血率。
- `EMPTY_CURRENT`：当前榜单为空，不把上一份全部判断为跌出榜。

数据库为空时显示可读空状态和 CLI 采集提示，不返回页面级错误。不存在的分区或快照显示明确的 404 状态。

## 7. 视频总结页面

### 7.1 提交与任务展示

- 顶部提供 Bilibili URL 输入框和“开始总结”按钮。
- URL 为空或不是受支持的 Bilibili 链接时，在输入区就近提示。
- 当前任务卡显示视频信息、任务状态、当前阶段、更新时间和可用操作。
- 历史任务列表显示视频标题、状态、提交时间、完成时间和结果复用标记。
- 页面刷新后根据任务 ID 恢复任务状态；任务未结束时轮询，进入终态后停止轮询。

### 7.2 进度阶段

任务阶段包括：

```text
等待执行
→ 获取视频元数据
→ 获取中文字幕
→ 解析文字稿
→ 切分文字稿
→ 分段总结
→ 合并总结
→ 完成
```

### 7.3 状态动画

- 处理中：橙金色环形加载动画、当前阶段文字和进度轨道。
- 成功：短暂的绿色完成动效，随后展开总结结果。
- 失败：红橙色错误动效，轻微抖动一次后显示稳定的失败标记和错误说明。
- 等待或重新排队：柔和呼吸效果，并显示排队状态。
- 所有动画遵守 `prefers-reduced-motion`；减少动态效果模式下改用静态图标和即时状态变化。

失败动画不得持续闪烁，不得妨碍用户阅读错误或点击重试。

### 7.4 结果展示

成功结果按结构化区块展示：

- 视频基本信息。
- 一句话总结。
- 详细内容总结。
- 分章节总结。
- 关键观点。
- 关键词。
- 重要时间点（结果存在时）。

API 和页面不展示元数据、字幕、文字稿或总结文件的本地绝对路径。

## 8. 总结任务持久化

SQLite 保存总结任务和执行记录。数据至少包括：

- 任务 ID、规范化视频标识和原始 URL。
- 状态、当前进度阶段和公开错误信息。
- 结构化总结结果。
- 创建、开始、更新和完成时间。
- 结果复用来源及重试关联关系。

状态流转为：

```text
PENDING → PROCESSING → SUCCEEDED
                     ↘ FAILED
```

### 8.1 去重与复用

- 同一 BV 号最多存在一个活跃任务。
- 重复提交正在处理的视频时返回已有任务。
- 已有成功结果时默认直接复用，避免重复调用模型。
- 手动重试失败任务时保留旧执行记录，并创建关联的新执行尝试。

### 8.2 重启恢复

- 服务启动时扫描 `PENDING` 和 `PROCESSING` 任务。
- 遗留的 `PROCESSING` 状态先安全转换为可重新执行状态，再自动排队。
- 恢复过程保持幂等，重复启动不会产生多个活跃执行。
- 用户仍可对失败任务执行手动重试。
- 服务关闭时停止接收新任务；未完成状态保留，供下一次启动恢复。

后台线程写入状态时使用短事务，降低与排行榜只读查询之间的锁竞争。

## 9. 后端接口

第一版接口：

```text
GET  /api/rankings/partitions
GET  /api/rankings/{partition}
GET  /api/rankings/{partition}/snapshots
GET  /api/rankings/{partition}/snapshots/{snapshot_id}

POST /api/summary-tasks
GET  /api/summary-tasks
GET  /api/summary-tasks/{task_id}
POST /api/summary-tasks/{task_id}/retry
```

Web 层负责请求校验和序列化，Service 层负责业务判断，Repository 层只负责 SQLite 查询与写入。HTML 或 React 组件不执行 SQL。

API 错误只返回稳定的错误代码和适合用户阅读的消息。Cookie、API Key、堆栈、原始模型错误和敏感本地路径不得进入 HTTP 响应。

## 10. 前端组件边界

公共组件包括：

- `AppShell`：整体布局和响应式导航。
- `SideNavigation`：桌面和平板导航。
- `MobileNavigation`：手机底部导航。
- `Panel`：统一面板容器。
- `StatusBadge`：排行榜和任务状态徽章。
- `MetricCard`：核心指标展示。
- `ChartPanel`：图表标题、图例、状态和内容容器。
- `DataTable`：Top 100 和历史任务数据表。
- `TaskAnimation`：等待、处理、成功和失败动画。
- `EmptyState` 与 `ErrorState`：空数据和错误状态。

页面组件负责组合和数据请求，公共组件保持无业务依赖。API 类型与显示模型分离，转换逻辑集中管理。

## 11. 响应式要求

- 桌面端保持参考图的信息密度和左右分栏关系。
- 平板端缩小侧栏和图表辅助区域，核心指标允许换行。
- 手机端使用底部导航，所有主内容改为单列。
- Top 100 表格在窄屏横向滚动，排名、标题和关键指标保持优先可见。
- 触控目标不小于 44 像素，键盘焦点清晰可见。
- 图表、动画和状态不能只依赖颜色传递含义。

## 12. 测试与视觉验证

### 12.1 后端测试

使用普通 pytest 测试函数，不使用测试类。覆盖：

- 首页、静态资源和 API 基本响应。
- 空数据库、有效榜单、陈旧快照、失败分区和不存在资源。
- 视频 URL 校验、任务创建、去重和成功结果复用。
- 状态持久化、服务重启恢复和手动重试。
- 总结成功、无字幕、网络或模型失败。
- HTTP 响应敏感信息清理。
- 现有排行榜采集和比较行为不回归。

### 12.2 前端与浏览器测试

测试代码使用普通函数，不写测试类。覆盖：

- 两个导航入口及响应式导航切换。
- 排行榜状态和 Top 100 渲染。
- 视频提交、任务轮询、终态停止轮询和手动重试。
- 等待、处理、成功、失败和减少动态效果状态。
- 桌面、平板和手机关键流程。

如果仓库接入 Playwright，则使用 Playwright 执行浏览器测试和截图；视觉检查同时使用当前可用的浏览器控制能力。

在桌面、平板和手机视口生成截图，并按参考图逐项核对：

- 外框、侧栏、主内容区和卡片的几何关系。
- 间距、圆角、层级、颜色和字体对比度。
- 图表、摘要区和数据区的信息密度。
- 处理中、成功、失败及减少动态效果模式。

发现明显偏差后调整实现并重新截图，直到关键布局、层级和视觉语言与参考图一致。

## 13. 编码约束

- Python 类和 TypeScript 类均不使用装饰器。
- 优先使用函数和组合；React 组件全部使用函数组件。
- Python、TypeScript 和浏览器测试均使用普通测试函数，不使用测试类。
- 不在网页中显示或编辑 Cookie、API Key 和其他密钥。
- 不改变现有 `--once` 和 `--schedule` 的运行方式。
- 不为了第一版本引入 Redis、Celery、Node 后端或独立任务进程。

## 14. 验收标准

- 通过 `http://localhost:8000` 打开网站，服务只监听本机地址。
- 侧边栏具有排行榜和视频总结两个入口，移动端具有对应底部导航。
- 排行榜读取现有 SQLite，可切换五个分区并查看 Top 100、快照时间和比较状态。
- 空数据、陈旧数据、失败分区和空榜单均有清晰状态。
- 可以提交 Bilibili URL，并看到持久化的任务状态、阶段和动画。
- 服务重启后未完成任务自动重新排队，失败任务可手动重试。
- 重复视频任务得到去重，已有成功结果得到复用。
- 成功结果结构化展示，失败信息不泄露敏感数据。
- 桌面、平板和手机布局通过浏览器截图检查。
- 现有采集、调度和比较测试继续通过。
